Baselines\n\n[](https://github.com/aims-foundations/paiec_baseline#paiec-predictor-baselines)\n\nThis repository provides reference predictors for the [Predictive AI Evaluation Competition](https://aimslab.stanford.edu/competition). Each predictor estimates the probability that an AI system will answer an item correctly, using the supplied attributes and any labels acquired during evaluation. The implementations offer starting points for developing predictors and comparing the value of test-time adaptation.\n\n| Predictor | Method | Acquisition | Requirements |\n|---|---|---|---|\n| [Bayesian Linguistic Evaluator (BLE)](https://github.com/aims-foundations/paiec_baseline/blob/main/ble/README.md) | An LLM retrieves public evidence and revises an explicit belief state. | Uncertainty sampling using the current prediction. | Public data payload and model API credentials. |\n| [Empirical Mean](https://github.com/aims-foundations/paiec_baseline/blob/main/empirical_mean/README.md) | The mean acquired response for the target subject–benchmark pair; 0.5 without matching labels. | The evaluator's default random policy. | Python standard library only. |\n| [Empirical Mean with BLE Acquisition](https://github.com/aims-foundations/paiec_baseline/blob/main/empirical_mean_ble_acquisition/README.md) | The same empirical mean predictor. | Uncertainty sampling from a separate BLE estimate. | Public data payload and API credentials for acquisition only. |\n\n## Repository layout\n\n[](https://github.com/aims-foundations/paiec_baseline#repository-layout)\n\n```\nble/                    Bayesian Linguistic Evaluator and its README\nempirical_mean/         Empirical mean predictor and its README\nempirical_mean_ble_acquisition/  Empirical mean with BLE acquisition\ntools/                  Data preparation, packaging, and local tests\ncheck_submission_zip.py Submission archive validator\nsubmit_api.py           Codabench authentication and submission utility\n```\n\nEach predictor directory contains `model.py`, implementing `predict(input, labeled) -\u003e float`. The two BLE acquisition variants also supply `labeling.py` for their policies. Build scripts place these entry points at the ZIP root, as required by the evaluator. Generated archives go into the ignored `dist/` directory; downloaded public training data go into the ignored `payload/` directory. Predictor setup and implementation details belong in each predictor's README.\n\n## Quick start\n\n[](https://github.com/aims-foundations/paiec_baseline#quick-start)\n\nRun commands from the repository root with Python 3.10 or later. The empirical mean baseline can be built and checked without downloading data or making API calls:\n\n```\npython tools/build_mean_zip.py\npython check_submission_zip.py dist/empirical_mean.zip\n```\n\nFor BLE, follow its [setup and walkthrough](https://github.com/aims-foundations/paiec_baseline/blob/main/ble/README.md#start-with-a-walkthrough). Its public build uses a blank configuration; a private submission build includes locally configured API credentials. Only credential-free archives should be shared. The BLE-acquisition mean baseline has its own [packaging instructions](https://github.com/aims-foundations/paiec_baseline/blob/main/empirical_mean_ble_acquisition/README.md#setup-and-packaging). All predictors use the competition's published [input and evaluation rules](https://aimslab.stanford.edu/competition).\n\n## Submitting to Codabench\n\n[](https://github.com/aims-foundations/paiec_baseline#submitting-to-codabench)\n\nInstall `requests` for the submission utility, then authenticate with an approved competition account. Login prompts for credentials and saves the API token at `~/.config/paiec/codabench-token` with owner-only permissions; it does not save the password or add the token to a submission archive.\n\n```\npython -m pip install requests\npython submit_api.py --login\npython submit_api.py dist/empirical_mean.zip\npython submit_api.py --list\npython submit_api.py --status SUBMISSION_ID\n```\n\nReplace the archive path with `dist/ble_submission.zip` to submit BLE. `CODABENCH_TOKEN` overrides the saved token, and `CODABENCH_TOKEN_FILE` overrides its location. Login, list, and status commands do not submit evaluations.\n\n## Developing additional baselines\n\n[](https://github.com/aims-foundations/paiec_baseline#developing-additional-baselines)\n\nAdd each predictor in its own directory with a method README, a `model.py` entry point, and an optional `labeling.py`. Shared development tools belong in `tools/`. Commit source, documentation, and synthetic tests; keep credentials, datasets, run outputs, and generated archives in ignored paths. The existing tests run without paid API calls:\n\n```\npython -m unittest discover -s tools -p 'test_*.py'\n```\n\nAfter selectively staging changes, review the staged diff and run the source check below. It detects prohibited artifact paths and common credential formats; manual review is still needed to establish the provenance of example data.\n\n```\ngit diff --cached\npython tools/check_public_source.py\n```\n\n## Citation\n\n[](https://github.com/aims-foundations/paiec_baseline#citation)\n\nIf you use these baselines in your research, please cite this repository:\n\n```\n@misc{paiec_baselines_2026,\n  author = {Truong, Sang and Salaudeen, Wale and Truong, Nhi and\n            Wang, Serena and Wang, Angelina and Guerdan, Luke and\n            Xiao, Ziang and Xie, Xing and Haber, Nick and Koyejo, Sanmi},\n  title = {{PAIEC} Predictor Baselines},\n  year = {2026},\n  howpublished = {GitHub repository},\n  url = {https://github.com/aims-foundations/paiec_baseline}\n}\n```\n\n## License\n\n[](https://github.com/aims-foundations/paiec_baseline#license)\n\nThe source code and documentation are licensed under the [MIT License](https://github.com/aims-foundations/paiec_baseline/blob/main/LICENSE).
