二、优先级排序：哪些方法值得复现？
优先级	方向	推荐论文 / 实现	为什么适合当前项目	主要风险

三、具体建议复现什么









1. Conditional / Attentive Neural Processes
首选实验

参考：Garnelo et al., ICML 2018；Kim et al., ICLR 2019

论文的核心是从一组已观察的 \((x_i,y_i)\) 推断新目标的条件预测。ANP 进一步允许目标 query 关注不同的支持样本，而不只使用统一的全局汇总。

Proceedings of Machine Learning Research
+1




官方代码：google-deepmind/neural-processes


建议复现的部分： 先复现 CNP 的 context encoder、集合聚合和 target decoder，然后再增加 ANP 的 target-to-context attention。使用已有 MiniLM 向量、item metadata 和允许揭示的标签。训练时按 Benchmark 构造 episodes，模拟六档预算。

与 R43 的实质区别： R43 是学习当前局部预测的可靠性；CNP/ANP 可以直接学习“支持样本集合如何决定查询 item 的预测函数”。这是不同的机制假设，不应把它视为已被 R43 否定。

实验进入条件： 先在来源内验证相对 R25 的增益，并通过 support-label permutation 确认模型确实利用了对应关系；若跨 Benchmark 仍无收益，不继续扩大 attention 层数。










2. Amortized IRT + Agent Psychometrics

参考：Truong et al., ICML 2025；Ge et al., 2026

这条路线不直接让 MLP 预测最终正确率，而是将 subject 能力和 item 难度分离，再组合成成功概率。Truong 的方法从题目内容估计难度；Agent Psychometrics 增加任务特征以及 LLM/scaffold 能力分解。

Proceedings of Machine Learning Research
+1




reeval 代码 · Agent Psychometrics 代码


建议复现的部分： 从 reeval/calibration/ 复现内容驱动的题目难度估计；再参考 Agent Psychometrics 的 experiment_new_benchmarks/ 与 experiment_new_agents/，处理新 Benchmark 和 subject 配置差异。

不必复现它的任务生成器、自适应评测全流程、仓库测试分析等 PAIEC 不具备相应输入的模块。

关键实验： 首先只看 held-out Benchmark 的 B0，要求比 0.5 的 Brier 0.25 更好，并检查大多数 Benchmark 的方向。若不能提供可靠先验，就不应让它污染 R25 的局部预测。










3. General Scales / ADeLe 的任务需求表示

参考：Zhou et al., Nature 2026

该论文将不同任务映射到一组通用认知需求与知识需求维度，再用这些维度预测不同 AI 系统的表现。它在新任务和新 Benchmark 上报告了优于部分黑盒 assessor 的结果。

Nature




代码与 Rubrics


建议复现的部分： 从 rubrics/ 和 predictive_power/ 入手，将 item 表示为少量结构化需求特征，例如逻辑推理、知识、信息定位、任务长度、开放式程度等，然后使用小 MLP 或原论文的随机森林对照。

我不建议一开始完整重训整个 ADeLe 体系。先选择最有希望、能够在比赛推理时一致获得的维度，验证它们是否在 held-out Benchmark 上比现有纯 MiniLM 特征提供增量。

最大约束： 不能仅在训练集用昂贵 LLM 预生成特征，却在隐藏测试没有同样的编码机制。必须使用可打包的本地编码器，或官方允许的 inference API，在实际时间和成本限制下生成特征。

4. IrtNet：作为第二阶段的多维 IRT 参考

参考：Chen et al., 2025

IrtNet 使用模型的多维能力向量、query 的区分度向量和难度，结合 MoE 学习响应概率。源码已公开，并提供新 Benchmark 预测入口。

arXiv
+1




IrtNet GitHub · 重点查看 src/benchmark_prediction.py


只有当较简单的 amortized IRT 已表现出一定可迁移信号时，再复现多维 discrimination/MoE。注意原仓库通过 majority vote 合并同一模型–题目的多个响应，而 PAIEC 必须保留重复 response 对 Brier 的贡献，不能直接复用这种标签处理方式。

5. DeBERTa Assessor：高成本备选

Analysing the Predictability of Language Model Performance 直接将 assessor 训练为“输入问题 → 预测 subject 是否成功”的模型。论文证实实例级预测存在一定跨任务可预测性，同时指出 OOD 泛化仍不足以保证实际应用。

数字对象标识符




这条路线适合在计算资源允许、且前几种结构化方法均未得到足够收益时尝试。不要简单把现有 2048–128–64 MLP 换成大 Transformer 后，就预期泛化问题自然消失。

四、最值得迁移到后续实验的 High-Level 认识
这部分比论文名称更重要，因为它决定如何从负结果中选下一步。
High-Level 认识	对 PAIEC 的具体启示
1. Representation 应表达可迁移结构，而不仅是文本相似性。	MiniLM/Hash 可以表示文本，却不一定表达模型完成任务所需的认知需求。参考 ADeLe，检验任务需求特征是否比原始 embedding 更适合 OOD
2. Model capability 不等于单一标量能力。	R15–R16 的 subject 能力标量失败不意味着所有能力模型失败。IRT 多维能力和任务需求交互提供了不同的假设，但必须审计可辨识性
3. Training objective 决定模型学到什么。	只在历史 response 上训练 Brier，未必学会利用少量新 Benchmark 标签。CNP/ANP 的 episodic training 更直接模拟运行时需要的推断
4. Parametric prior 与 contextual evidence 是两种不同的信息源。	历史跨任务先验和当前 31 个标签不能被不加区别地混合；应分别验证哪一种信息在什么预算下可靠
5. 信息存在不等于信息可被可靠估计。	R48 的额外标签 oracle 与 R34/R49 的失败共同提醒：已知正确的修正方向，不代表有限样本可以可靠估计其幅度
6. Capability 和评分指标必须分开。	论文的 AUROC、汇总 RMSE、ECE 改善，都不保证 pair-equal Brier ALC 改善；所有方法最终必须回到同一六预算协议

其中，我认为 第 3 条与第 4 条目前最具有操作价值。

它们提示你：当前可能不需要一个更大的模型，而是需要一个真正以“新 Benchmark 内有限证据条件预测”为学习任务的模型。CNP/ANP 是这个认识的直接实现路径；Amortized IRT 则提供了另一个方向，即为标签不足时构造更可靠的先验。

五、建议的实际执行顺序
我建议采取一个短周期、有进入条件的执行路线，而不是立即把所有模型完整复现。

1. 首先复现 CNP → ANP 的核心模块。 直接继承 R25 已有特征和合法标签接口，使用相同训练来源与 benchmark-grouped 验证。先看条件预测有没有新增收益，再决定是否训练完整模型。

2. 并行建立 Amortized IRT 的轻量复现。 优先复现内容预测难度和 subject 条件化，不做主动选题或任务生成。先用 B0 和 B1 的 held-out 结果筛选，不能胜过 0.5 的先验就停止融合。

3. 如果上述方法缺乏可靠的跨任务表示，再试 ADeLe 风格的任务需求特征。 优先复现少量通用维度的可重复编码，而不是完整语义标注系统。只有确认新增信息价值，才考虑接入 ANP 或 IRT。

对每一步，都先比较冻结的 smoothed mean 和 R25，而不是只与早期弱 MLP 比较。若候选有局部收益，再进入 5,242-pair、三个种子的统一评价与既有 Gate。因为这些公开 Benchmark 已被反复使用，结果仍须注明自适应选择偏差，不能当作全新盲测。
关于复现时的竞赛规则
我重新核对了官方规则：预训练模型可以使用并需披露；竞赛专用训练与微调只允许使用 benchmark inventory 列出的数据来源；评分时可以访问指定提供商的 inference API，但禁止 web search、browsing 和 grounding。模型可以在提交包内打包，或通过 models.txt 提前预取，不能任意依赖评分时下载。

AIMS




这意味着 ANP、IRT 和 ADeLe 风格方法都具有一定部署空间，但必须单独核查依赖、推理速度、标注和可用输入。
六、最后的选择建议
如果目标是在 10 月 30 日截止前尽可能提升比赛成绩，而不是产出一篇全新的方法论文，我会这样取舍：

最值得立即复现：CNP/ANP。 它与你已有的局部 item 信号直接对应，能最大程度复用 R25 的工作，并且原理和参考代码明确。

最值得作为独立探索：Amortized IRT / Agent Psychometrics。 它有机会改善现有局部方法没有覆盖好的零标签与低标签预算，但也最需要提防跨 Benchmark prior 的负迁移。

最有 high-level 启发：General Scales / ADeLe。 它提醒我们：真正能迁移的可能是任务要求的结构，而不是 Benchmark 名称、单一模型能力或文本表面相似度。

暂缓： 继续放大旧 MLP、增加普通 metadata、重复调整固定平滑强度、复制完整 IrtNet MoE、继续扫描 R33 的幅度系数，以及在 hosted 共享标签契约未确认前大规模开发 collaborative prediction。

这三条主要方向并不互斥，但应该先证明各自有独立增益，再组合。这样既能充分借用已有成熟方法，也能避免下一阶段再次陷入 R1–R50 式的大量低收益变体搜索。
